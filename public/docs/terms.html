Terms

Every term the board, the lessons and the reports underline, in a sentence or two. In the app, hover an underlined word for the same definition; here they are all at once.

termwhat it means
ANNApproximate nearest neighbour search: finding similar vectors fast by giving up a little recall instead of comparing them all.
autoscalingAdding instances when load rises and removing them when it falls. New ones serve only after their warm-up.
availability zoneAn isolated data centre within a region. Spreading over zones survives losing one.
back-pressureA slow consumer signalling upstream to slow down, instead of letting queues grow without bound.
backlogMessages waiting in a queue or stream for a consumer.
backoffWaiting longer before each retry (with jitter), so retries spread out instead of arriving together.
bottleneckThe component that runs out of capacity first. It caps the whole system: scaling anything else changes nothing.
bulkheadA separate share of threads per dependency, so one slow dependency cannot take all of them.
burn rateHow fast the current error rate uses up the error budget: 1× lasts the month, 14.4× spends 2% of it in an hour.
cache hit rateThe share of reads a cache answers itself; the misses go on to the origin.
capacityThe requests a second a component can serve before it has to queue or refuse.
CDNContent delivery network: caches near the users answer what they can; the rest goes to the origin.
CFS throttlingLinux CPU limits (Kubernetes limits) cut a container off for the rest of each 100 ms period once it used its quota, adding stalls to its latency.
circuit breakerStops calling a dependency that keeps failing, for a while, then lets a few probes through to see if it recovered.
cold cacheA cache that restarted empty. Until it refills, its misses stampede the origin.
cold startThe time a new serverless instance (or container) takes before its first request: loading the runtime and code.
cold storageArchive tiers (S3 Glacier) that cost pennies a GB to keep and are slow, and priced, to read back.
CPU limitThe CPU time an edge function may use per request (about 1 ms on CloudFront Functions, 10 ms on Workers Free); past it, it is killed.
edge functionSmall code that runs at the CDN’s edge before the origin (CloudFront Functions, Cloudflare Workers), near the user.
error budgetWhat the SLO allows to fail over a period: at 99.9% a month, about 43 minutes of full outage.
failoverMoving traffic from a failed component to a standby — for a database, promoting a replica.
fallbackA degraded answer served instead of failing — a cached page, a default — while the real one is unavailable.
fan-outOne request calling many others — every partition, every follower’s timeline. It waits for the slowest.
goodputRequests answered successfully per second — throughput minus what failed.
headroomCapacity kept free above the load you have, for spikes and for losing an instance.
health checkA periodic probe that marks a target down after a few failures, so traffic is routed away from it.
HNSWHierarchical navigable small world: the graph most vector databases search. Fast while it fits in memory, slow from disk.
hot keyOne key with a large share of the traffic. It lands on one shard or partition, which saturates while the others idle.
idempotencyDoing an operation twice has the same effect as once — what makes retrying a payment safe.
instancesIdentical copies of a component. Behind a load balancer each takes a share of the traffic.
JIT warm-upA new JVM or .NET instance runs slow, interpreted code until its compiler has compiled the hot paths. The compiler needs CPU the requests leave free, so an instance that is busy from its first second can stay slow.
latencyHow long a request takes, from the caller’s side.
Little’s lawRequests in flight = arrival rate × time each spends. It links concurrency, throughput and latency.
load balancerSpreads incoming requests across a fleet of identical instances, and stops sending to ones that fail their health checks.
load sheddingRefusing work on purpose when overloaded, so the work accepted still finishes in time.
N+1Running one more instance than the load needs, so losing any one keeps the rest within capacity.
network partitionThe network between two parts of a system fails while both keep running, each unable to reach the other.
originThe system behind a cache or CDN that answers its misses.
p50The median response time: half the requests are faster, half slower.
p99The response time 99% of requests beat. The slowest 1% — at a million requests a day, ten thousand people.
p99.9The response time 99.9% of requests beat: the tail that large fan-outs make everyone wait for.
partitionA slice of a stream or table. A stream subscriber can run at most one consumer per partition.
prefix limitS3 takes 5,500 reads or 3,500 writes a second per key prefix; a hot prefix gets 503 SlowDown.
provisioned concurrencyServerless instances kept warm ahead of demand, so they start no cold; billed by the hour, used or not.
queueWork waiting for a free worker. A bounded queue sheds what would wait too long.
rate limitA cap on requests a second; past it, requests get HTTP 429 instead of service.
recallThe share of the true nearest neighbours an approximate search returns. 0.99 walks far more of the index than 0.95.
refresh intervalHow often a search index makes new writes searchable (1 s by default). Until the next refresh, searches miss them.
replicaA copy of a database that follows the primary. It serves reads, and can be promoted if the primary dies.
replication lagHow far a replica is behind its primary. Reads there miss the latest writes; a failover loses them.
req/sRequests a second: how much traffic arrives, or how much a component can take.
restoreBringing an archived object back from Glacier Flexible Retrieval: minutes to hours, paid for per request and per GB.
retriesCalling again after a failure. They rescue transient errors and multiply the load on a struggling dependency.
retry amplificationEach failed call retried N times turns one request into up to N + 1 calls, on the component least able to take them.
retry budgetA cap on retries as a share of calls (here 10%), so retries cannot snowball.
scale outAdding instances (horizontal scaling). Scaling up means a bigger box instead.
scatter-gatherSending a request to many partitions in parallel and waiting for all of them; the slowest sets the latency.
shardA horizontal partition of the data: each shard holds part of the keys and serves them on its own.
SLOService level objective: the target a system is held to, e.g. “errors under 1% and p99 under 300 ms”.
stale DNS answerA client still using a cached DNS answer that points at a target which has since died.
threadsIn thread-per-request servers, each request in flight holds a thread, waiting on its calls included.
throughputRequests handled per second.
timeoutHow long a caller waits for an answer before giving up and counting the call as failed.
token bucketA rate limiter that allows bursts: tokens refill at the rate, each request spends one.
TTLTime to live: how long a cached answer (a DNS record, a cache entry) is kept before it is asked for again.
utilisationThe share of a component’s capacity in use. Waiting grows steeply past about 70%.
utilisedIn use as a share of capacity. Waiting grows steeply past about 70%.
warm-upHow long a new instance takes before it serves: booting, starting the runtime, filling caches.
write-behindA cache that acknowledges writes and flushes them later: fast, but writes are lost if it dies first.
