Backtest on real data

Strategies

A strategy is any infrastructure change, written as a short YAML file. The backtest replays it over your real history: thirty times, with every uncertain capacity drawn from its band, paired against the system as built.

Every option

name: Graviton + autoscaling
description: Move the API to Arm and let it follow load
changes:
  - service: api
    arch: arm                  # Graviton pricing (×0.8 per vCPU-hour); set perf: from a benchmark
    autoscale: { min: 2, max: 8, targetCpu: 0.6, warmupS: 60, cooldownS: 300, intervalS: 15, metricWindowS: 60 }
  - service: catalog
    cache: { hitRate: 0.8, latencyMs: 1, costPerHour: 0.219 }   # a cache in front
  - service: orders-db
    readReplicas: 1            # reads split over the primary and its replicas
    readShare: 0.8
  - service: search
    replicas: 3                # a fixed count
    cpu: 2                     # cores per replica
    memoryGb: 4
  - service: payments
    capacityRps: 120           # override, e.g. after removing a lock
    zone: us-east-1a           # placement → data-transfer pricing
  - endpoint: "*"              # or one endpoint id
    retries: { attempts: 2, budget: 0.1 }   # client retries, extra load capped at +10%
    timeoutMs: 3000
changewhat the backtest does with it
replicasA fixed count. In-process dependencies follow their host.
autoscaleA target-tracking scaler on its own clock: it evaluates every intervalS on CPU averaged over metricWindowS, waits warmupS before a new replica serves, and cooldownS before scaling in. A 60-second CloudWatch average reacts later than a 15-second Prometheus window, and the backtest shows the minutes that costs.
cpu, memoryGbResize. A CPU-bound capacity scales with the cores left after the idle baseline, including how much it serves once collapsed. A service that is not CPU-bound today becomes CPU-bound when the new limit is below the CPU it uses. Price scales with vCPU and memory.
arch: armGraviton pricing (Fargate: $0.03238 vs $0.04048 per vCPU-hour). Throughput per vCPU is assumed equal unless you give perf, and the report says so.
perfA throughput multiplier per replica, from your own benchmark of the new instance family.
capacityRpsOverride the fitted capacity, e.g. after removing a lock.
cacheA cache in front of the service. A hit skips that service and everything it calls. Priced as ElastiCache cache.r7g.large unless given.
readReplicasReads (readShare, default 0.8) split over primary and replicas; cost × (1 + replicas).
zone, regionPlacement. Bytes between components in different zones or regions are priced per GB.
retries, timeoutMsPer endpoint or "*": client retries add load where requests fail, capped by the budget; slower answers than the deadline are failures.

Where strategies come from

  • A file — written by hand, kept next to the code, passed to hindcast backtest or dropped on the backtest screen.
  • The Changes tab — edit live; the backtest reruns as you type.
  • The board — open any moment, edit the system, press Backtest these edits.
  • Audit fixes — each verified fix in the failure audit has a Backtest button when the board came from a backtest.
  • A pull request — hindcast diff-strategy --base old/ --head new/ reads Kubernetes manifests before and after: replicas, CPU and memory limits, HPAs, kubernetes.io/arch.
