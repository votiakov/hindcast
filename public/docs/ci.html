Backtest on real data

CLI, pull requests, MCP

The same backtest runs without the app: a command-line tool, a ready-made check that backtests every infrastructure pull request, reports to attach to a review, and tools for AI assistants.

The command line

hindcast export-prometheus --url http://prometheus:9090 --start 2026-09-01 --end 2026-09-15 --out telemetry/
hindcast import    telemetry/hindcast.import.yaml --out dataset.json
hindcast calibrate dataset.json --holdout 0.3 --out model.json
hindcast backtest  model.json dataset.json graviton.yaml autoscale.yaml --last 14d --html report.html
hindcast headroom  model.json [strategy.yaml]
hindcast accuracy  model.json
hindcast outage    model.json slack-2021-01-04 [strategy.yaml]
hindcast diff-strategy --base old/deploy --head deploy --model model.json --out strategy.yaml
hindcast verify-change --model model.json --dataset dataset.json --base old/deploy --head deploy --comment pr.md

In the repository: npm run sim -- <command>. Anywhere else: the native binary, npm run cli:build → engine-rs/target/release/hindcast (no runtime needed). Every command takes --json.

The HTML report

--html report.html writes one self-contained page to attach to a design review. Open the HotROD report.

  1. One verdict per strategy

    The same sentences as the app and the pull-request comment.

  2. p99 over the history

    Measured, as built, and every strategy with its band, against the SLO.

  3. Errors, cost, cumulative cost, error budget

    Then the model's accuracy and the full Markdown report.

The pull-request check

A GitHub Action. In the workflow of the repository that holds your manifests:

permissions: { contents: read, pull-requests: write }
steps:
  - uses: actions/checkout@v4
  - uses: votiakov/hindcast@v1
    with:
      model: .hindcast/model.json
      dataset: .hindcast/dataset.json
      manifests: deploy/            # or terraform-plan: plan.json

On a pull request it:

  • reads the manifests as they were at the pull request's base commit and turns the diff into a strategy: replicas, CPU and memory limits, HPAs, kubernetes.io/arch (a Terraform plan needs no base);
  • backtests it against the last 14 days of recorded traffic with hindcast verify-change, the same verdict and confidence an agent gets from verify_change;
  • writes the result to the job summary and to one pull-request comment, updated in place on every push;
  • fails the check when the verdict is fail (fail-on: inconclusive is stricter, never only reports).

The repository holds the calibrated model and the recent history in .hindcast/; the action downloads the binary for the runner. No secrets beyond GITHUB_TOKEN. Every input and output, and a full comment: docs/ci.md in the repository. @v1 resolves once the repository has a v1 tag; until then pin a release.

What it posts on a pull request that trims the HotROD frontend to 50 millicores:

frontend CPU 1 → 0.05 — fail · confidence low. It saves $23/month; it would have caused 18 minutes out of SLO, the worst on Oct 7 at 16:28 UTC (frontend at 71% of capacity (3.9 req/s on 1 × 5.5 req/s), 132 ms wait).

The check fails, as it should. Under the verdict the comment lists $/month with its basis (your bill, or list prices), the minutes out of SLO and failed requests with their 10–90% bands, the worst moment, why the confidence is what it is, a table of as built against the change, and the model's accuracy record.

A hand-written workflow doing the same with the CLI, and a script that assembles a demo repository, are in examples/backtest-ci.

Cards and clips

Any backtest result as a post-sized card, or a clip of the chart drawing itself and then the verdict. In the app: Card ↗. From the CLI: hindcast backtest … --card card.json, then npm run record -- --card card.json renders MP4 and PNG stills.

  1. The verdict

    The focused strategy's sentence.

  2. Measured, as built, what would have happened

    Measured p99 as bars (red where it broke the SLO), the model's as-built replay dashed, the strategy in amber.

  3. How far to trust it

    Every card carries the model's measured accuracy, misses included.

For AI assistants (MCP)

npm run mcp starts an MCP server over stdio; Claude Code picks it up from .mcp.json. Twenty-six tools. The eleven that let an agent work on a live system itself (connect to Prometheus and Jaeger, collect, calibrate, verify a change or a Terraform plan) are in For AI agents. The rest:

toolwhat it does
backtest_strategybacktests strategies (objects or YAML) over a recorded history and returns the Markdown report
replay_outagereplays a public outage against a model, as built and with strategies
audit_resiliencewhat breaks first in a design, and what it costs; verified, priced fixes
simulate, analyzeone run (fluid or discrete-event), or Monte Carlo with confidence intervals
trace_requestsampled requests through one component, hop by hop: queue waits, work, and where and why each failed, as data and as the lines the app's trace strip shows (hindcast simulate … --engine des --trace <component> from a shell)
compare_architectures, find_breaking_point, optimize_costrank variants, find the max req/s within SLO, find the cheapest sizing that meets it
import_terraform, import_kubernetesinfrastructure code → an architecture, with the assumptions to confirm
show_architecture, open_in_appa live canvas inline in hosts that support MCP Apps, or a link into the app
list_components, validate_architecturethe component catalogue; schema and lint
