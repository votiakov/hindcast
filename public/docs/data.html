Backtest on real data

Bring your data

Hindcast works from files you export: metrics, traces and the cloud bill. Nothing connects to your systems, and nothing leaves your machine.

Drop the files on the backtest screen

  1. Drop anywhere

    An import manifest with the files it names (Prometheus or CloudWatch exports, OTLP traces, a CUR or GCP bill), or a dataset.json and model.json made by the CLI, plus any strategy YAML files. The app imports, calibrates and backtests in the browser.

  2. Or pick them

    Open files… does the same with a file picker.

What each source gives the model

sourceformatsgives
Request metricsPrometheus query_range JSON, CloudWatch get-metric-data output, long or wide CSV (Grafana exports)load per service and endpoint; latency (p50, p95, p99, mean) and errors per bucket
Container metricsthe same formats; presets for cAdvisor and KubernetesCPU used, CPU and memory limits, replicas, network: CPU per request, capacity per replica, replica-hours
TracesOpenTelemetry OTLP JSON lines (the collector's file exporter), one OTLP document, or Jaeger JSONthe topology; which services each endpoint visits and how often; how many milliseconds of each request each service owns (the critical path); self time per service; payload sizes; uninstrumented databases, caches and queues as their own components
The billAWS Cost and Usage Report (legacy or 2.0 columns), GCP billing export (CSV or JSON lines)$ per replica-hour, per request and per GB for each component; spend no component explains, shown separately

Missing values stay missing: a gap in a scrape is not a quiet minute.

The import manifest

One YAML file names the files and says what each series is. Units are converted (s, ms, us, percent, ratio, cores, millicores, rpm, count-per-period).

name: checkout
step: 1m                              # bucket size (default: the metrics' own resolution)
rename: { checkout-svc: checkout }    # raw names → one id across every source
metrics:
  - prometheus: metrics/rps.json      # a query_range response
    metric: rps                       # rps errorRate p50Ms p95Ms p99Ms meanMs cpuCores cpuPercent
    by: service_name                  #   cpuLimitCores replicas netTxBps netRxBps memoryBytes
  - prometheus: metrics/endpoint-rps.json
    metric: rps
    by: service_name
    endpointBy: http_route            # endpoint-level series
    methodBy: http_request_method
  - cloudwatch: cw/getmetricdata.json
    map:
      req: { service: api, metric: rps, unit: count-per-period }
      cpu: { service: api, metric: cpuPercent, scale: 2 }   # % of a 2-vCPU instance → cores
traces:
  - file: traces/*.jsonl
    sampling: 0.1                     # share of requests traced (the real share is measured)
    ignore: [loadgenerator]
billing:
  - cur: bill/cur-2026-09.csv
    tag: user:service                 # the cost-allocation tag naming the component
    resources: { "db-7XK2": orders-db }
placement:                            # zones and regions, to price data transfer
  checkout: { zone: us-east-1a, region: us-east-1 }
model:                                # hints for calibration
  slo: { p99Ms: 400, errorRate: 0.01 }
  timeoutMs: 5000                     # the client deadline: slower answers are failures
  hostedBy: { sqlite: checkout }      # in-process dependencies seen in traces
  endpoints:
    "checkout POST /orders": { slo: { p99Ms: 800, errorRate: 0.005 } }

Export from Prometheus in one command

export-prometheus runs ready-made queries and writes both the JSON files and the metrics: block of the manifest. Presets: otel-spanmetrics (the OpenTelemetry Collector's spanmetrics connector), http-server (OpenTelemetry HTTP histograms, with per-route series), spring (Spring Boot / Micrometer), ingress-nginx (every request at the edge; it takes precedence over span metrics for the same service), cadvisor, kubernetes (kubelet + kube-state-metrics, grouped by the workload that owns each pod; CPU requests stand in where no limit is set). --selector 'namespace="shop"' scopes every query.

hindcast export-prometheus --url http://prometheus:9090 \
  --start 2026-09-01 --end 2026-09-15 --preset otel-spanmetrics,kubernetes --out telemetry/
# add traces and the bill to telemetry/hindcast.import.yaml, then:
hindcast import    telemetry/hindcast.import.yaml --out dataset.json
hindcast calibrate dataset.json --holdout 0.3 --out model.json

import prints what each source gave. calibrate prints every component with its capacity, what limits it, how well the model reproduces it and why. Next: how the model is fitted.
