Bottleneck

Backtest infrastructure changes on your real production data before they ship, and simulate any architecture to find what breaks first and what it costs.

Bottleneck has two halves that share one engine.

with your real datawithout data
Inputmetric exports (Prometheus, CloudWatch), OpenTelemetry traces, the cloud bill (AWS CUR, GCP)a design you draw, write as YAML, or import from Terraform or Kubernetes
Modelfitted from the data, with its accuracy shown and anything it can't explain flaggedcatalogue numbers, or your own
Questionwhat would this change have done to the last two weeks?what breaks first, and what does it cost?
Answer$ saved or spent, minutes out of SLO, failed requests, the worst moment and why, with confidence bandsa risk register with verified, priced fixes; comparisons; breaking points
WhereBacktest, the CLI, a pull-request checkLive, Lessons, Sandbox, Compare, Studio

Accuracy is measured, not claimed. Three open demo systems were run under load with their telemetry recorded. Calibrated on one run, the model predicted runs it never saw: p99 within 2–10%, breaking points within 0–13%, cost within 0–3%. See accuracy.

Start

npm install
npm run dev            # the app on http://localhost:5173 — the docs are at /docs/
npm run sim -- …       # the CLI
npm run mcp            # the MCP server for AI assistants
  • Open the Backtest tab: the three reference systems are built in. Then bring your own data.
  • Or start on Live, a system already failing, and follow the next move.
  • Looking for a specific question? Use cases. Want the full list? Everything it does.
